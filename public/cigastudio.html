HELP & DOCUMENTATION

This page explains the main CIGA workflow: importing your avatar, adding interaction objects, connecting your VTuber software, connecting the CIGAIS Discord Worker, creating events, testing your setup, and preparing the final viewport.

01

UNDERSTANDING CIGA

CIGA is an interaction layer that sits between your stream events and your avatar. It handles the interaction itself while your normal VTuber software remains responsible for displaying and tracking the avatar.

STREAM EVENT → CIGA → ACTION → AVATAR / VIEWPORT
3D
CIGA works with compatible 3D VTuber workflows through VMC / OSC. The default VMC sender port is 39539.
2D
CIGA connects directly to VTube Studio and uses its calibration system to estimate where interactions should occur.
VMC IMAGE TRACKING
Image movement and orientation tracking is only available when CIGA receives valid VMC tracking data.

This is intended for VMC-based workflows. Normal 2D Live2D / VTube Studio operation does not use VMC image tracking.

When valid VMC tracking is unavailable, tracked images remain at their configured position and rotation.
02

AVATARS

CIGA's imported 3D character workflow is designed for VRM avatars.

Live2D models do not need to be imported into CIGA. For 2D, CIGA uses its virtual Stickman Calibration while the actual model remains inside VTube Studio.

01
Open IMPORT CHARACTER and select your compatible .VRM avatar.
02
Load the character into CIGA.
03
Run MAP AVATAR so CIGA can create the required bone and interaction mapping.
2D USERS
You do not import your Live2D model into CIGA. Create and configure the Stickman Calibration avatar instead, then keep your actual model inside VTube Studio.
03

INTERACTION OBJECTS

Interaction objects are separate from character imports. CIGA currently accepts GLB and GLTF files for 3D objects.

GLB / GLTF
These formats are used for objects such as boxes, bricks, balls, props and other items that can be thrown or used during interactions.
PREVIEW
Use the object preview to check the model, starting scale and general appearance before using it during a live interaction.
IMPORTANT
VRM is for characters.
GLB / GLTF are for interaction objects.

These are separate import workflows and should not be confused with one another.
OPTIMIZER
The optimizer prepares imported assets for use inside CIGA. It can remove unnecessary heavy lighting data and reduce oversized textures where appropriate.
AUTO SCALE
Auto Scale is mainly intended for unusually large models. It provides a more practical starting size without forcing every object into the same scale.
RECOMMENDED
Run imported objects through the CIGA optimizer whenever possible, especially when using large textures or complex models.
04

INTERACTIONS

The Interaction page is where you test how objects behave when they reach the avatar.

OBJECT
Choose which object should be launched.
TARGET
Choose the HitPoint, such as Head, Chest, Arm, Shoulder or Leg.
PHYSICS
Adjust values such as speed, force, spawn position and impact behaviour.

Use this page to find values that feel correct before creating the corresponding stream event.

IMPACT INTENSITY
Impact Intensity controls how strongly the avatar reacts when an object reaches its target. The available range is 0 to 5.
05

EVENTS

Events connect stream triggers to actions inside CIGA. Instead of configuring every interaction separately, you can build an event containing the effects you want.

TRIGGER → EVENT → ACTIONS
01
Open the EVENTS section and create or select an event.
02
Choose the event trigger, such as FOLLOW, SUBSCRIBE, BIT, RAID or a compatible Channel Point reward.
03
Add one or more actions to the event.
04
Configure each action and save the event.
05
Test the event using Mock Events before using it during a live stream.
INTERACTION
Launches configured interaction objects with the selected physics, amount and target settings.
PLAY_SOUND
Plays a selected audio file when the event occurs.
DISPLAY_IMAGE
Displays an image on a configured avatar target. Position, scale, rotation and mirroring can be edited through the 3D image preview.
EXPRESSIONS
The event architecture is designed to support additional avatar reactions such as expressions as the system continues to develop.
MULTIPLE ACTIONS
One event can contain multiple actions.

For example:
FOLLOW
→ Interaction
→ Sound
→ Image

The configured actions can occur together rather than requiring a manually defined sequence.
CHANNEL POINTS
Reward filters can be left empty to accept compatible rewards generally, or configured with a specific reward name when you want one event to react only to that reward.
06

MOCK EVENTS

Mock Events let you test your configuration without waiting for a real Twitch or StreamElements event.

PHYSICS
Test object movement, impact and reaction strength.
EVENTS
Verify that triggers and multiple actions are configured correctly.
MEDIA
Test sounds and displayed images before going live.
07

EXTERNAL CONNECTIONS

V TUBE STUDIO
Start the VTube Studio API and enable VTube Studio Output in CIGA. Accept the permission request shown by VTube Studio.
VMC / VSEE FACE
Enable VMC Output and configure the receiving application to use UDP port 39539.
STREAM ELEMENTS
Connect StreamElements when you want external stream events to trigger your configured CIGA events.
CIGAIS WORKER
Connect the CIGAIS Worker when you want CIGA to communicate with the CIGA Discord interaction system.
VMC PORTS
VMC Sender: UDP 39539
VMC Receiver: UDP 39541
VMC IMAGE TRACKING
VMC Image Tracking only operates when CIGA receives valid VMC tracking data.

The feature is optional and does not affect normal 2D Live2D / VTube Studio operation.
FIRST VMC CONNECTION
After changing VMC settings for the first time, restarting both CIGA and the receiving application may be required.
08

CIGAIS WORKER // DISCORD SETUP

The CIGAIS Worker is the Discord connection used by CIGA to communicate with the CIGAIS interaction system.

Before connecting the Worker in CIGA, the CIGAIS Discord bot must be installed in the Discord server that you want to use.

REQUIRED
The bot must be a member of the target Discord server.

Entering a Guild ID in CIGA without adding the bot to that server will not establish a working Worker connection.
01
Use the official CIGAIS bot invite:
ADD CIGAIS BOT TO DISCORD
02
Log into the Discord account that owns or has permission to manage the target server.
03
Select the server where CIGA will be used and authorize the CIGAIS bot.
04
Confirm that the CIGAIS bot appears in the server member list.
BOT OAUTH2 CONFIGURATION

The CIGAIS bot uses the following OAuth2 scopes:

bot
applications.commands

The bot invite also includes the permissions required by the current CIGAIS Worker configuration.

SLASH COMMANDS
Use Slash Commands is the relevant permission for the bot's Discord application commands.

The applications.commands OAuth2 scope is also included in the invite so Discord application commands can be registered.
FIND YOUR GUILD ID

CIGA needs the Discord Guild ID of the server where the CIGAIS bot has been installed.

01
Open Discord User Settings.
02
Open Advanced and enable Developer Mode.
03
Right-click the Discord server you want to use.
04
Select Copy Server ID.

The copied number is your Guild ID.

CONFIGURE CIGA
01
Open the OUTPUT configuration in CIGA.
02
Open the CIGAIS WORKER source.
03
Enter the copied Discord Guild ID.
04
Save the configuration and connect the CIGAIS Worker.
DISCORD SERVER → CIGAIS BOT → GUILD ID → CIGAIS WORKER → CIGA
AUTO CONNECT
CIGA supports automatic connection for the CIGAIS Worker.

Enable AUTO CONNECT ON LAUNCH in the CIGAIS Worker source configuration after the Guild ID has been configured.

If no Guild ID is provided, CIGA intentionally skips the Worker connection instead of attempting an unnecessary connection.
SECURITY
The Discord bot invite link can be shared with people who need to add the CIGAIS bot to their server.

Never share the Discord Bot Token, Client Secret, or other private authentication credentials.
BOT STATUS
The Worker connection requires the Discord bot to remain present in the selected server.

Removing the bot from the server prevents the CIGAIS Worker from operating with that server.
09

PERFORMANCE

CIGA prepares imported resources before they are needed during live interaction.

PRE-WARM
Resources can be prepared and cached so that repeated interactions do not need to perform the same expensive loading operation again.
OPTIMIZATION
Optimizing imported assets is recommended, particularly for complex objects and large textures.
INITIAL LOAD
The first launch can take anywhere from a short time to several minutes.

This depends on the number and complexity of imported assets, texture sizes, storage speed and system hardware.

A longer initial load does not necessarily mean CIGA has frozen. The application may still be preparing and caching resources.
RECOMMENDED
Keep imported assets optimized and avoid unnecessarily large textures or extremely complex models whenever possible.
10

TROUBLESHOOTING

LONG STARTUP
CIGA may still be preparing assets. Large or complex imports can take considerably longer. The optimizer is recommended for imported objects.
AVATAR DOES NOT REACT
Check that the correct avatar is loaded and mapped, then test the interaction directly before checking the event configuration.
EVENT DOES NOT FIRE
Check the external connection first, then verify that the event trigger and filters match the event being received.
OBJECT CAUSES INSTABILITY
If the problem started after importing a new object, remove that object and test CIGA again.
CIGAIS WORKER
If the Worker does not connect:

1. Confirm that the CIGAIS bot is inside the Discord server.
2. Confirm that the Guild ID belongs to that server.
3. Confirm that the Guild ID is entered correctly in CIGA.
4. Check that the bot has the permissions required by the Worker.
5. Check the CIGA Worker connection log.
DEBUGGING APPROACH
Test the simplest configuration first:

One avatar → One object → One interaction

Then add events, media and additional objects one at a time. This makes it easier to identify which part is responsible for a problem.
FULLSCREEN WINDOW POSITIONING
When opening the configuration window from a fullscreen launcher, the window may occasionally initialize in an incorrect position. Restarting the affected window normally resolves the issue.
RAPID REWARD EVENTS
Some reward-based interactions may currently require a short cooldown between activations. Triggering several rewards immediately one after another may cause a later event to be missed.
11

FINAL VIEWPORT

The Final Viewport brings the configured avatar, camera, interaction objects, events and connected outputs together for actual use during a stream.

01
Load and verify your avatar.
02
Check your objects and event configuration.
03
Test the setup using Mock Events.
04
Confirm external connections such as StreamElements, VTube Studio, VMC and CIGAIS Worker when required.
05
Press TAB to enter the transparent overlay workflow when preparing the viewport for OBS.
OBS
The CIGA viewport can be captured by OBS as part of the streaming setup. When the interface is hidden, use Alt+Tab to return to the CIGA window.
